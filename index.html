Section I: Bezier Curves and Surfaces

Part 1: Bezier curves with 1D de Casteljau subdivision

De Casteljau's algorithm finds a point on a Bezier curve by repeatedly interpolating between neighboring points using the same value of t. In my evaluateStep function, I loop through each neighboring pair, calculate (1 - t) * points[i] + t * points[i + 1], and add the new point to a result vector. Each step gives us one fewer point, so we repeat until just one is left. That's the point on the curve at t.

Part 2: Bezier surfaces with separable 1D de Casteljau

For Bezier surfaces, we use the same algorithm in two directions across a grid of 3D control points. My evaluateStep works just like Part 1, but with Vector3D points. In evaluate1D, I repeat that step until one point is left. Then, in evaluate, I evaluate each row using u and collect the results. I evaluate those points using v to get the final point on the surface at (u, v).

Section II: Triangle Meshes and Half-Edge Data Structure

Part 3: Area-weighted vertex normals

1. Implementing area-weighted vertex normals

I implemented the area-weighted vertex normals by iterating through all the triangles adjacent to a vertex using the half-edge data structure. For each triangle, I calculated its normal using the cross product of two edge vectors. Since the magnitude of the cross product is proportional to the triangle's area, larger triangles automatically contribute more to the resulting normal. I added these normals together and normalized the final vector to get the unit normal at the vertex.

I first check if the edge is on a boundary and return without changing it if it is. Part 6: Loop subdivision for mesh upsampling

1. Implementation and debugging tricks

I implemented Loop subdivision in five passes:

  1. Compute and store the updated position of each original vertex using \(p'=(1-nu)p+u\sum_{i=1}^{n}p_i\), where \(n\) is the number of neighbors, \(u=3/16\) when \(n=3\), and \(u=3/(8n)\) otherwise.
  2. Compute and store the new vertex position for each edge using \(p_e=\frac{3}{8}(a+b)+\frac{1}{8}(c+d)\), where \(a,b\) are the endpoints and \(c,d\) are the opposite vertices of the two adjacent triangles.
  3. Split every original edge.
  4. Flip newly created edges that connect an old vertex to a new vertex.
  5. Copy the stored positions into the vertices.

A useful implementation trick was computing all positions before changing connectivity, so every weighted average uses the original mesh. I also saved the original edge iterators in a vector to avoid accidentally splitting newly inserted edges. I used isNew flags to identify which edges to flip: the two halves of an original split edge are marked old, while the new cross edges are marked new. Keeping these steps separate made it easier to track connectivity and position updates. My implementation skips meshes containing boundary edges.

Repeated subdivision rounds sharp corners and edges because the position updates average neighboring vertices across those features. The cube shrinks and becomes progressively smoother, while the mesh becomes denser. 3. Cube asymmetry and preprocessing

When I repeatedly subdivided dae/cube.dae, the cube became slightly asymmetric, as seen in the subdivision sequence above. Its geometry is approximately symmetric, but its triangulation is not: each square face has a diagonal, and the original corner vertices have between three and six neighbors. Corresponding corners therefore receive different neighborhood averages. For example, a corner near \((1,1,-1)\) moves to approximately \((0.625,0.625,-0.8125)\) after the first iteration, showing unequal movement along the three axes.

To make subdivision symmetric, I split the diagonal on each of the six square faces. Each face then has a center vertex connected to all four corners, forming four triangles. Every original corner has six neighbors, and corresponding neighborhoods match under the cube's rotations and reflections. The Loop weights therefore act symmetrically, preserving symmetry through subsequent subdivisions apart from tiny coordinate inaccuracies in the input.

Six diagonal splits are sufficient for this construction; no edge flips are required. Flips alone change the diagonal orientations without removing their directional bias. The additional refinement used to reduce rounding in question 2 uses both splits and flips.
