Section I: Bezier Curves and Surfaces

Part 1: Bezier curves with 1D de Casteljau subdivision

De Casteljau's algorithm finds a point on a Bezier curve by repeatedly interpolating between neighboring points using the same value of t. In my evaluateStep function, I loop through each neighboring pair, calculate (1 - t) * points[i] + t * points[i + 1], and add the new point to a result vector. Each step gives us one fewer point, so we repeat until just one is left. That's the point on the curve at t.

I used six control points for this curve. These screenshots show each evaluation level, followed by the completed curve. Click any image to see it at full size.

Part 2: Bezier surfaces with separable 1D de Casteljau

For Bezier surfaces, we use the same algorithm in two directions across a grid of 3D control points. My evaluateStep works just like Part 1, but with Vector3D points. In evaluate1D, I repeat that step until one point is left. Then, in evaluate, I evaluate each row using u and collect the results. I evaluate those points using v to get the final point on the surface at (u, v).

Section II: Triangle Meshes and Half-Edge Data Structure

Part 3: Area-weighted vertex normals

1. Implementing area-weighted vertex normals

I implemented the area-weighted vertex normals by iterating through all the triangles adjacent to a vertex using the half-edge data structure. For each triangle, I calculated its normal using the cross product of two edge vectors. Since the magnitude of the cross product is proportional to the triangle's area, larger triangles automatically contribute more to the resulting normal. I added these normals together and normalized the final vector to get the unit normal at the vertex.

Part 4: Edge flip

I first check if the edge is on a boundary and return without changing it if it is. Otherwise, I save the six half-edges around the two triangles, along with their vertices, edges, faces, and outside twins. I reconnect the shared edge to the two opposite vertices, then use setNeighbors to rebuild the two triangle loops. Finally, I update the half-edge pointers for the vertices, edges, and faces. Nothing gets added or deleted, and the operation only touches this small neighborhood, so it takes constant time.

Keeping the half-edges labeled h0 through h5 and saving the original pointers before changing anything helped keep the connections straight. There wasn't a big debugging issue with the flip itself. The checks passed for 20 repeated flips, including the pointer connections, unchanged element counts, and leaving boundary edges alone.
